# 编码与数据格式

## **编码与数据格式**

### **1. 数据类型一览**

每个字段通过 f 标识数据类型：

|  |  |  |  |
|---|---|---|---|
| f值 | 类型 | JSON表示举例 | 说明 |
| 1 | bool | "0" / "1" | 注意：用字符串，不是true/false |
| 2 | uint8 | "255" | 0-255 |
| 3 | int8 | "-10" | -128到127 |
| 4 | string | "BYD" | 普通文本 |
| 5 | uint16 | "480" | 0-65535 |
| 6 | float | "25.5" | 去尾零，禁用科学计数法 |
| 7 | object | {...} | JSON对象，保持原生类型 |
| 8 | array | [...] | JSON数组，保持原生类型 |
| 9 | double | "114.123456" | 双精度浮点 |
| 10 | uint32 | "100000" | 0-4294967295 |
| 11 | int16 | "-100000" | 有符号16位整数 |
| 12 | int32 | "-100000" | 有符号32位整数 |
| 13 | byte array | 无 | 用于表示字节数组 |

常见错误提醒：

• ❌ "v": true — bool 类型要用字符串 "0" 或 "1"

• ❌ "v": 25 — 数值类型要用字符串 "25"

• ❌ "v": "1.230e4" — 禁止科学计数法

### **2. JSON 编码要点**

数值统一使用字符串表示（如"25"而非 25），以与云家电物模型保持一致。接收端需持有 Profile 的 Schema（f 类型信息）进行反序列化。

二进制字段（密钥、签名等）用 f:4（string）承载，内容采用 base64 编码（默认，膨胀 33%，适合 BLE 传输）；调试场景可选 hex 编码（膨胀 100%）。

### **3. CBOR 编码要点**

CBOR 编码比 JSON 更紧凑，适用于 BLE 带宽受限场景或串口传输环境。CBOR 具有以下优势：

• 二进制字段直接用 byte string，无需 base64 编码（节省 33%体积）

• 整数键压缩（高频字段用整数代替字符串）

**JSON vs CBOR** 对比（以 3200B 的 Profile 为例）：

|  |  |  |
|---|---|---|
| 指标 | JSON | CBOR |
| 原始体积 | 3200B | ~2400B（紧凑 25%） |
| base64 膨胀 | +33% | 0%（无膨胀） |
| 分片数量（MTU=244） | 27 片 | 12 片 |
