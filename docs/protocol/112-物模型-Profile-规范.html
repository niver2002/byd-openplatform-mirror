物模型 Profile 规范

来源：软件开发协议 / 直连接入协议 / 比亚迪智能设备开放接入协议 / 物模型 Profile 规范 · 文档 ID 112 · 原始页面

物模型 Profile 规范

1. Profile 是什么

Profile 就是设备的"能力表"。

Profile 用 JSON 格式描述设备有什么功能、每个字段是什么类型、读写权限是什么、值范围是多少。

车机拿到 Profile 后，就知道：

  • 这个设备能干什么（有哪些服务）
  • 每个服务有什么字段（温度、开关、模式等）
  • 哪些可以读、哪些可以写、哪些会主动上报

Profile 跟设备的交互可以用"简历+对话"类比：

  • Profile：简历，告诉对方"我叫什么、能干什么"
  • Runtime Message：对话，实际交流"读一下温度"、"把风扇开到 3 档"

2. 顶层结构

Profile 的顶层结构如下：

JSON
{
    "did": "000020_aabbccddeeff_ivi_BLEWifi",
    "desc": "BYD Smart Pet Cage",
    "profile_ver": "1",
    "$meta": {
    "init_pipeline": ["sec"],
    "voice_feedback": true
    },
    "srvs": {
    "dinf": { ... },
    "sec": { ... },
    "stat": { ... }
    }
}
字段含义说明
did设备唯一标识格式建议：<modelid>_<mac/sn>_<type>_<transport>
desc设备描述人类可读的设备名称
profile_ver物模型版本用于缓存校验，避免每次连接重复拉 Profile
$meta中间件行为元数据声明车机侧中间件的行为（握手阻塞、业务错误拦截等）
srvs服务集合设备所有服务的定义


3. 服务定义规范

3.1 服务分类

服务分为两类：系统服务（协议控制面）和业务服务（应用数据面）。

3.1.1 系统服务（协议控制面）

系统服务由中间件自动管理，上层 App 通常不感知。

服务键全称必选说明
secSecurity条件必选安全握手/会话管理。需要加密时必须实现
ftxFile Transfer可选文件分片传输
otaOTA Upgrade可选OTA 固件升级


3.1.2 业务服务（应用数据面）

业务服务由上层 App 通过 AIDL 接口读写控制。

服务键全称必选说明
dinfDevice Information必须设备基本信息（制造商/型号/SN/版本）
btryBattery Service可选电池电量/充电状态
statState按需设备运行状态属性
actionAction按需命令/动作/控制
eventEvent按需事件告警上报
modeMode按需设备名称/模式设置


3.2 $meta 中间件行为

$meta 是 Profile 顶层的可选对象，告诉车机中间件该做什么，这些行为对上层 App不可见。

字段含义举例
init_pipeline连接初始化流水线["sec"] 表示安全握手完成后才通知 App 设备已连接（time_sync 等步骤定义待后续补充）
voice_feedback语音反馈通道true 表示 t:1 为语音TTS 反馈通道，网关拦截不上透给 App，仅触发TTS 播报


init_pipeline 的执行前提是：《BLE传输层规范》-4.连接初始化与业务就绪 中规定的链路准备动作已经完成。只有当 init_pipeline 中的步骤全部成功后，车机才可以将设备标记为“业务就绪”并通知 App。

若 init_pipeline 包含 "sec"，则 sec 是业务放行前的必经门禁步骤；即使handshake_mode 为 "manual"，也只是改变握手触发方，不改变“握手完成前禁止业务通信”的规则。

4. 字段 Schema

每个特征字段用以下 Schema 定义：

字段必须含义
f必须数据格式标识（见第 《编码与数据格式》）
per必须权限编码（见本文第 5 章节）
v必须当前值/默认值
u可选单位（如 "℃"、"%"）
min/max可选值域范围
s可选步长（如温度步进 1℃）
desc可选枚举说明/描述


5. 权限编码 per

权限用三位编码，格式为 "WRN"（从高位到低位）：

位位置含义
Wbit2（高位）Write 可写
Rbit1（中位）Read 可读
Nbit0（低位）Notify 可上报

常用组合：

编码含义典型场景
"010"只读设备版本号、温度（只看不改）
"011"只读+上报温度（可读，设备也会主动上报变化）
"100"只写/命令重置命令、发送指令
"111"读写+上报风扇模式（可读可改，设备也会上报变化）

举例：

• "010" → 只能读，不能写，不会上报

• "011" → 可以读，设备会主动上报，但不能写（只读传感器）

• "111" → 可以读、可以写、设备也会主动上报
